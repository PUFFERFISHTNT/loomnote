# 织记 × VCPToolBox · 借鉴报告

> 参考项目：[lioensky/VCPToolBox](https://github.com/lioensky/VCPToolBox)（2.3k★，VCP 部署在 AI 模型 API 与前端应用之间的工业级基建）；同名的协议级简化版工具箱见 [ANGLE404/VCPToolBox](https://github.com/ANGLE404/VCPToolBox)。
> 结论：借六样、不借三样；只吸收设计理念与协议形态，代码与文档全部独立实现。

## 1. 借六样，不借三样

**值得借的六样：**
1. 中间层引擎位置（前端永不直接对话模型）
2. 纯文本工具协议（不依赖 Function Calling，天然容错）
3. 变量占位符即配置（系统提示词插槽，零代码定制）
4. 上下文「引力」式按需注入（信息流向 AI，而非 AI 主动查询）
5. 冷热双通道记忆 + 语义级模型路由（成本控制）
6. 清单化的插件扩展机制

**明确不借的三样：**
1. AGI「自主生活」整套理念——织记的 AI 是学习助手，不是常驻居民；产品边界更窄、更聚焦、更好交付。
2. 分布式多机部署与多前端接管——织记本地优先，单机 SQLite 起步。
3. 代码与文档文本——两仓库均为 **CC BY-NC-SA 4.0**（署名·非商用·相同方式共享），织记全部独立实现。

## 2. 六条借鉴的落地映射

| VCPToolBox 设计 | 织记落点 | 实现要点 |
|---|---|---|
| 中间层引擎 | AI 引擎层夹在 UI 与模型间，前端只讲控制协议 | headless 引擎 + 控制面；界面零感知模型与工具 |
| 纯文本工具协议 | 内部指令协议 `:::tool 名称 {JSON5 参数}` | 正则+宽松恢复解析；坏指令降级不中断；不依赖 Function Calling |
| 变量占位符 | 提示词模板插槽 + 设置界面改变量 | `{{注意力包裹}}` / `{{薄弱点}}` / `{{风格偏好}}` / `{{复习状态}}` |
| 上下文引力 / L1–L4 粒度 | 打开笔记时引擎重组分级「注意力包裹」 | 图谱邻域自动吸起、无关内容折叠；替代「AI 主动检索」老模式 |
| 冷热双通道 + 选模路由 | 热库（近期学习/薄弱点）常驻上下文，冷库归档索引 | 重任务强模型、轻任务弱模型；令牌成本全链路可控 |
| 插件清单化 | 解析器/同步器/出题器/演示组件全部清单注册 | manifest：名称/类型/配置项/可调命令；未来开放第三方扩展 |

## 3. 核心升级：上下文引力机制

传统检索是「AI 主动拉取」——它不知道要去拉什么。VCP 把模型翻过来：信息按需**流向** AI。织记照搬这个姿势：每次打开笔记，引擎在后台重组一个「注意力包裹」——

- **L1** 当前笔记 · 全文
- **L2** 关联知识点 · 摘要
- **L3** 图谱邻域 · 标签级
- **L4** 其余 · 折叠为索引

再把该包裹经变量插槽注入引擎上下文。效果：用户问「背包问题为什么这样递推」，前置于它的「前缀和」摘要、易混的「完全背包」对比标签自动在场——讲解天然连贯，token 账单同步打薄。知识图谱因此从「一张好看的图」升级为「AI 讲课时真正的感知环境」；手动搜索（语义/图谱遍历/全文）降级为备用通道。

## 5. 对产品方案的净影响

1. 4.4「检索三位一体」从主路径降级为备用检索；主路径改为「注意力包裹 + 变量注入」。
2. AI 输出协议由「裸 JSON Schema」升级为「指令协议 + 容忍解析」双轨：生成为主、解析容错。
3. 引擎能力模块统一走清单注册，为第三方扩展预留。
