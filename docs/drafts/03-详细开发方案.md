## 1. 本阶段范围（开发测试版）

**包含（In）：**

- Electron 工程骨架，macOS / Windows 双端可跑，GitHub Actions 双平台 CI 矩阵
- 数据层：SQLite 建库 + 迁移机制 + 本地资源库
- 导入解析：Markdown、PDF、图片（OCR）、HTML/URL（Word/Excel 下一阶段）
- 渲染引擎三模式：正文 / 演示（沙箱 iframe）/ 源码（CodeMirror）
- AI 引擎：模型供应商自由接入（OpenAI 兼容/自定义端点任意可加、多供应商并存、按任务路由）、流式输出、指令协议、注意力包裹、笔记生成器
- 记忆引擎：参照 VCP 源码架构自建的本地记忆系统（分层记忆/残差金字塔语义版/三通道联想召回/折叠注入/规则蒸馏自进化，零外部服务依赖，详见 docs/05）
- 实时生成：流内工具回环 + md/HTML 渐进渲染 + 演示双缓冲帧 + 查询特征预分析驱动的语义级模型路由（详见 docs/06）
- 知识图谱：节点/边 CRUD、力导向画布、关联面板、增量合并 + Diff + 版本快照
- 复习：自测题生成与交互判分、FSRS 排期（v1 简化）
- 设置：AI 密钥与模型配置、数据目录

**排除（Out）：**

- 安装包 / 代码签名 / 自动更新（Electron Forge 配置仅预留）
- 飞书 / Notion 真实同步（同步适配器接口与桩实现保留，联网版后续阶段）
- 账号体系、云备份、移动端；Word/Excel 解析；多用户

## 2. 技术选型（定版）

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js 20+（Electron 内置同档）、pnpm 9 | 双端一致；pnpm 省磁盘、锁文件稳定 |
| 桌面壳 | Electron（33+ stable）+ electron-vite | Node 生态直上（pdfjs/sqlite/ffmpeg-like 链路）、dev 模式 HMR；electron-vite 官方脚手架成熟 |
| UI | React 18/19 + TypeScript 5 + Vite | 大生态；TS 全链路强类型 |
| 状态 | zustand | 轻量、无模板，适合本地优先应用 |
| 路由 | react-router（HashRouter） | 应用以 `file://` 加载，hash 路由最稳 |
| 样式 | 自建设计系统（CSS 变量 + 手写样式） | 不引入 UI 框架，视觉完全自主（产品差异化） |
| 编辑器 | CodeMirror 6 + @codemirror/lang-markdown | 源码模式三栏预览的首选 |
| MD 渲染 | markdown-it + KaTeX + mermaid + highlight.js + 自研插件（`:::toc`/色块/`[[双链]]`/演示插槽） | 生态成熟，插件定制自由 |
| PDF | pdfjs-dist（主进程 worker） | 文本+版面坐标提取，双端一致 |
| 图片处理 | sharp（裁剪）+ 视觉模型 OCR；native 异常时降级 @napi-rs/canvas | 已验证的裁剪工作流需要坐标级控制 |
| 存储 | better-sqlite3 + 自建迁移器 + 记忆引擎专用表 | 同步 API 心智简单；prebuild 支持 Electron ABI |
| 向量 | MVP：JS 余弦相似度（嵌入由 LLM API 生成）；升级位：sqlite-vec | 开发测试版数据量小，先零依赖跑通 |
| 图谱可视化 | Cytoscape.js + fcose 布局 | 大图性能与布局算法最省心 |
| 复习算法 | ts-fsrs | FSRS 官方 TS 实现 |
| 模型接入 | Model Provider 框架（IProvider 适配层）：OpenAI 兼容端点（火山方舟/DeepSeek/Moonshot/智谱/本地 Ollama·LM Studio 等）、Anthropic 协议、用户自定义 HTTP/SSE 端点 | 与 DSH Desktop 同思路——任意模型 API 都能接入；多供应商并存 + 按任务路由；原生 fetch + SSE，不引重型 SDK |
| 测试 | vitest + @playwright/test（Electron 冒烟） | 单元 + 界面冒烟 |
| 代码质量 | ESLint（flat config）+ Prettier + TS strict | 双端工程底线 |

## 3. 双端策略（Windows + macOS）

| 关注点 | 策略 |
|---|---|
| 路径 | 一律 `path.join` + `app.getPath('userData')`，禁止硬编码 `/` 或 `\`；资源库位置可配置 |
| 字符集 | 读文件统一 UTF-8 + BOM 探测；md 管线统一行尾 `\n`（写入时按端归一） |
| 原生模块 | better-sqlite3 / sharp 用 prebuild；CI 双矩阵里跑 `electron-builder install-app-deps` 校验 ABI |
| CI | GitHub Actions `matrix: [macos-14, windows-latest]`：`pnpm i → lint → typecheck → test → build` |
| 每日验证 | 双端每日构建产物上传 artifact；开发以 macOS 为主力、Windows 靠 CI/远程机冒烟 |
| 字体 | 正文字体栈双端兜底（mac: PingFang SC/Songti；win: Microsoft YaHei/SimSun）；KaTeX/mermaid 资源全本地打包，不引 CDN |
| 打包预留 | 应用 id 占位 `com.loomnote.dev`；Electron Forge 配置写入骨架但本阶段不执行 make |
| 经验复用 | 双端差异调试（如 Electron 环境变量、托盘、文件对话框差异）沉淀入 `WORKFLOW_LESSONS.md` |

## 5. 数据模型（SQLite）

```sql
-- 迁移器管理，schema_version 表记录版本
CREATE TABLE imports (              -- 导入记录
  id TEXT PRIMARY KEY, kind TEXT, source_path TEXT, status TEXT,
  log TEXT, created_at INTEGER, finished_at INTEGER
);
CREATE TABLE notes (                -- 笔记（IR 载体）
  id TEXT PRIMARY KEY, title TEXT, body_md TEXT, front_matter TEXT, -- JSON
  status TEXT, import_id TEXT, created_at INTEGER, updated_at INTEGER
);
CREATE TABLE resources (            -- 资源文件（原稿/裁剪图/重绘 SVG）
  id TEXT PRIMARY KEY, import_id TEXT, kind TEXT, rel_path TEXT,
  meta TEXT, checksum TEXT, created_at INTEGER
);
CREATE TABLE knowledge_nodes (      -- 知识节点
  id TEXT PRIMARY KEY, note_id TEXT, title TEXT, summary TEXT,
  tags TEXT, mastered INTEGER DEFAULT 0, strength REAL DEFAULT 0,
  embedding TEXT, last_reviewed_at INTEGER, created_at INTEGER
);
CREATE TABLE edges (                -- 知识关联边
  id TEXT PRIMARY KEY, from_id TEXT, to_id TEXT, relation TEXT,
  weight REAL DEFAULT 1, created_at INTEGER
);
CREATE TABLE quiz_items (           -- 题目（结构化 JSON 字段）
  id TEXT PRIMARY KEY, node_id TEXT, qtype TEXT, question_md TEXT,
  options TEXT, answer TEXT, explanation_md TEXT, difficulty INTEGER
);
CREATE TABLE review_logs (          -- 复习记录（FSRS 输入）
  id TEXT PRIMARY KEY, node_id TEXT, item_id TEXT, grade INTEGER,
  scheduled_at INTEGER, reviewed_at INTEGER, stability REAL, difficulty REAL
);
CREATE TABLE versions (             -- 笔记版本快照
  id TEXT PRIMARY KEY, note_id TEXT, kind TEXT, patch TEXT,
  created_at INTEGER
);
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT); -- JSON
CREATE TABLE schema_version (version INTEGER);
```

要点：

- 主键一律 TEXT UUID，跨端安全；时间戳 ms。
- embedding 存 JSON 数组文本（MVP）；升级 sqlite-vec 时加列迁移。
- 资源文件落 `userData/assets/{import_id}/`，库内存相对路径（双端可迁移）。

## 6. 核心模块设计

### 6.1 导入解析管线（main 进程）

`IParser { id; supports(kind): boolean; run(input): Promise<ParseResult> }`，清单注册。
`ParseResult = { markdown: string; assets: [{srcRelPath, meta}] ; warnings: string[] }`

| Parser | 实现要点 |
|---|---|
| markdown-parser | 原样入 IR；front matter 抽取；行尾归一 |
| pdf-parser | pdfjs-dist 逐页 getTextContent + 版面坐标；图片/公式区按坐标框裁剪（zoom 2.6~3.4 经验）；落资源库并生成 `![](path)` 引用 |
| image-parser | 视觉模型 OCR → 结构化 md；原图入库；重绘 SVG 由 AI 引擎后续任务完成 |
| html-parser | 正文抽取（清洗导航/广告）→ markdown 化 |
| url-parser | 抓取 → 走 html-parser → 打来源标记 |

任务模型：导入 = 队列任务（pending → parsing → done/failed），进度经 `ai:event` 同款事件通道推 UI，可取消、可重试。

### 6.2 Markdown IR 与指令协议（shared）

- IR 扩展：`$$…$$`、```mermaid、`[[双链]]`、`:::toc`、`:::色块`、front matter（`title/tags/难度/关联/来源`）、演示插槽 `:::demo {id}`。
- 指令协议（AI → 应用，`:::tool` 块）：`:::tool 动作名 {JSON5 参数}`；解析走正则 + JSON5 恢复，坏块降级为原文提示而非中断。

### 6.3 三模式渲染引擎（renderer）

| 模式 | 实现 |
|---|---|
| 正文 | markdown-it 全插件链 → DOMPurify 消毒 → 注入设计系统样式；[[双链]] 渲染为可点击链接；`:::demo` 处内嵌演示组件 |
| 演示 | AI 生成的 HTML 片段装入 `iframe sandbox="allow-scripts"` + 严格 CSP；与主应用经 `postMessage` 白名单桥接（事件名 + origin 校验）；**渲染纪律校验器**：开标签独占行、唯一根容器、样式前缀隔离、结构扁平、无 backdrop-filter、动画只 opacity——不及格自动重生成 |
| 源码 | CodeMirror 6 + 右侧实时预览（复用正文渲染器） |

### 6.4 AI 引擎（main 进程）

- **模型接入层（Provider 框架）**：`IProvider` 接口 + 适配器注册表——任意模型 API 均可接入：OpenAI 兼容端点（火山方舟、DeepSeek、Moonshot、智谱、本地 Ollama / LM Studio 等）、Anthropic 协议、自定义 HTTP/SSE 端点（用户填 baseURL + key + 模型名即可，预设模板一键带出）。设置界面：多供应商并存、连通性测试、模型能力标注（视觉/推理/上下文长度）；密钥经系统钥匙串加密存储，不落明文。</li>
- **LLM 客户端**：统一流式通道（所有 provider 归一为同一 SSE 事件流，中继 renderer：`ai:stream` delta / tool-block / done / error）。
- **任务队列**：串行 + 优先级 + 可取消；崩溃自动拉起断点续跑。
- **注意力包裹**（借鉴 VCP）：buildAttention(noteId) → L1 全文 + L2 关联摘要 + L3 邻域标签 + L4 折叠索引；注入提示词 `{{注意力包裹}}` 等变量插槽。
- **模型路由**：定义「推理 / 轻量 / 视觉 / 向量」四类任务角色，每类可映射到任意供应商任意模型；默认映射自带，用户改一行即换全链路模型来源。M2 起叠加**语义级动态路由**：查询特征预分析器（逻辑深度/熵/覆盖度/新颖度）动态选档与定注入预算（docs/06 §2.2）。
- **生成器**：笔记整理（分章/速记卡/自测）、演示 HTML、题目（JSON Schema）、标签器、摘要器——统一走「角色/步骤/检查项」模板套件。
- 密钥与端点存 settings 表，仅本机；日志脱敏。

### 6.5 知识图谱与注意力包裹

- 节点/边 CRUD + FTS5 搜索；邻接查询（前置链/延展图/对偶）。
- 画布：Cytoscape.js + fcose；节点点击出侧卡（摘要、关联、出处）。
- 增量合并：新导入 → 嵌入向量 → 与存量节点余弦比对 → AI 出变更集（增/改节点、建边、冲突标记）→ UI Diff 预览 → 批准合并（先写 versions 快照）。
- MOC 自动生成、孤岛检测（度=0 节点提醒）。

### 6.6 复习引擎

- 题目 JSON Schema 见 §5 quiz_items；交互组件：选择/填空/判断 + 即时判分 + 解析。
- 判分结果：写 review_logs（FSRS grade）→ 更新节点 mastered/strength；错题归因节点「薄弱」。
- 复习队列：ts-fsrs 排期 → 今日队列 → 抽认卡视图。

### 6.7 版本快照

编辑保存时自动快照（versions 表，patch=md 级 diff（diff-match-patch））；界面支持快照列表 → 预览 diff → 一键恢复（恢复前再存当前离线快照）。

### 6.8 同步适配器（本阶段仅接口 + 桩）

`ISyncAdapter { id; connect(credentials); push(note); pull(...); }`；飞书（官方 OpenAPI，沿用单 `$`/≤800px/3 次每秒/先副本四约束）与 Notion 适配器列入下一阶段，本阶段仅注册桩 + 设置界面占位。

### 6.9 记忆引擎（详见 docs/05 · VCP 源码级调研版）

参照 VCP 记忆体系源码结构实现：写入层（分块→幂等去重→嵌入→Tag→资产世代化）、召回层（三通道过取→去重→核心 tag 传播 boost→结构重排→直锚原文读出）、注入层（预算守卫+折叠块+上下文快照审计）、进化层（行为流水→规则蒸馏→版本化生效）。全部本地、随应用启停。

## 8. 验收标准（开发测试版）

1. **双端可跑**：macOS 与 Windows 全新克隆 → `pnpm i && pnpm dev` 成功启动；CI 矩阵绿。
2. **导入**：10 页以上 PDF 讲义 30s 内解析完成；正文、公式、插图（坐标裁剪目检无切边/渗字）落库正确。
3. **AI 整理**：单讲次生成结构化笔记（主标题/目录/章节/速记卡/自测），流式输出界面可见。
4. **演示**：≥3 个知识点生成 HTML5 演示，沙箱内正常交互、无样式泄漏；不合格片段被校验器拦截并自动重生。
5. **图谱**：≥20 节点自动入库，画布缩放/搜索/点选侧卡正常；增量导入生成变更集可审可撤。
6. **复习**：≥5 题自测即时判分；错题使对应节点 mastery 下调并进入 FSRS 排期。
7. **版本**：改笔记 → 快照 → Diff 预览 → 恢复，全链路无损。
8. **本地主权**：断网可启动可编辑；笔记可整库导出为 md+assets 文件夹。
9. **记忆自进化**：用户纠正一次偏好（如「公式用单 `$`」）→ 之后同类生成自动遵守；记忆包裹装配前后快照可回看；全部记忆随应用启停、零外部服务依赖。
10. **实时生成体验**：从按「整理」到首帧出内容 ≤2s 且过程连续无白屏（本地模型除外）；AI 演示片段产出即渐进可见；打断后可从检查点分支续流；坏段自动重写而非整卡重来。
