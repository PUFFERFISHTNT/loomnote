# 织记 LoomNote · 技术选型评审与全网最新实践调研（2026-07）

> 评审对象：`docs/drafts/03-详细开发方案.md`、`docs/drafts/06-源码洞察与全栈优化方案.md`
> 调研窗口：2024–2026 发布/维护动态（以 web_search/web_fetch + 官方仓库一手页为准）
> 结论口径：开发测试版阶段（pnpm dev、不打包）——打分按「本阶段能跑通 + 为下一阶段留好退路」双重标准。

## 0. 调研总览（一句话版）

方案骨架**成熟度很高、无需推倒重来**。三个必须立刻改的点：① Electron 33 已 EOL（当前 stable 为 43，内置 Node 24），方案里的「Node.js 20+ / 33+」基线全部过时；② 升级位 sqlite-vec 上游已实质停滞，需要改写备选清单；③ 演示 iframe 安全模型少了两层（不可变 meta CSP + MessageChannel 桥），补上即可达到工业级标准。其余选型（better-sqlite3、markdown-it 链、ts-fsrs、Cytoscape、自研 Provider/流式管线）全部**维持**并有 2024–2026 新证据加持。

|---|---|---|---|---|

| 2 | UI 栈：React 18/19 + TS 5 + zustand + HashRouter + 自建设计系统 | **9/10** | **维持** | React 19 已稳定一年半，直接上 19 即可；zustand + HashRouter（file:// 加载）是本地优先桌面应用的标准答案；电子-vite HMR 生态成熟。自建设计系统对「视觉即产品差异」的织记是正确决策，无需引 UI 框架。 |

| 6 | 演示沙箱：iframe sandbox="allow-scripts" + CSP + postMessage 桥 | **7.5/10（补齐后 9）** | **维持架构，补两层** | 方向正确但只落实了沙箱第一层的「一半」。2026 年公认的 AI 生成 HTML 三件套：① `sandbox="allow-scripts allow-forms"` **永不加 allow-same-origin**（二者同加，内页可自我解除 sandbox）；② `srcdoc` 首字节注入**不可变 meta CSP**：`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:`（meta CSP 一经解析不可改，并封死 img/script src 外联外泄通道）；③ **MessageChannel 私有端口桥**替代裸 postMessage + 每请求白名单校验（端口对象不泄漏、iframe 导航即自动断开）。织记方案还应在纪律校验器里加「外联资源=0 预检」。 |
| 7 | 图谱：Cytoscape.js + fcose | **8/10** | **维持** | Cytoscape.js 由 Consortium 接手后回到活跃节奏（3.31.0，2025-01），fcose 稳定。<10k 节点的知识图谱场景它是电池最全的选项。设定明确的换路阈值：**>10k 节点或交互帧率不达标 → 换 AntV G6 v5（性能强）或 Sigma.js v3（WebGL、大规模）；**画布组件保持接口隔离，GraphView 只暴露渲染契约。 |
| 8 | 复习：ts-fsrs | **9/10** | **维持** | FSRS 的行业地位 2024–2026 已被充分背书：**Anki 24.11 起 FSRS 成为默认调度器并延续至 Anki 6**；FSRS-6 已随 fsrs4anki 6.x 释出；ts-fsrs（官方 TS 实现）v5.x 活跃维护。织记「v1 简化」姿态正确，直接用最新 5.x 即可。 |
| 9 | 流式管线：SSE + 流内工具回环 + 渐进 md 解析 + 双缓冲 | **8.5/10** | **维持（自研）** | 主进程做 SSE 中继、渲染层做增量消费是桌面端的正确形态，与 Vercel AI SDK（Web 优先生态）重叠面小，不建议为了名义上的「成熟方案」引入。可参考的成熟实践：增量渲染走**分段缓冲 + 防抖 + keyed 分块 memo**，而不是整文档重渲染；morphdom 长期低活跃、不引入。需补工程护栏（见 §3-6）。 |
| 10 | AI Provider 层：自研 IProvider 适配 + 原生 fetch/SSE | **8/10** | **维持** | 多供应商并存、自定义端点、按任务路由正是重型 SDK 管不好的面，自研薄适配层正确。补两点执行件：各 provider 归一事件流用 **zod schema 校验**（Anthropic 协议的 SSE 事件结构与 OpenAI 兼容流差异必须单测覆盖）；密钥落 **Electron safeStorage**（系统钥匙串），不要存明文 settings。 |

## 2. 风险登记表

| # | 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|---|
| 1 | **Electron/Node 基线过时**：33 已 EOL 一年半，按旧基线起工程后无安全补丁、与未来 Chromium 行为脱节 | 高 | 工程返工 + 安全面裸露 | 起步即锁当前 stable **43.x**（Node 24.17）；文档 §9 删除「Node.js 20 前置」，改为 24；升级策略写入 §3/§12：每 2 个 major 窗口内完成一次升级并跑双端冒烟 |
| 2 | **原生模块 ABI 破坏**：better-sqlite3/sharp 与 Electron 运行时 AB 错位（Node ABI ≠ Electron ABI 的历史坑仍在） | 中 | 启动即崩、数据面不可用 | 维持 prebuild 路线（bs3 v13 Node-API prebuild + sharp N-API 预编译），**CI 双矩阵增加「加载冒烟」**：`new Database(':memory:')` + `SELECT sqlite_version()`、sharp metadata()；升级 Electron major 时先跑 `electron-builder install-app-deps` 试跑验证；ABI 对记录进 WORKFLOW_LESSONS（daintree 项目公开踩坑案例可作模板） |
| 3 | **双端差异**：字体/排版/路径/行尾/对话框行为在 Windows 与 macOS 不同 | 高 | 公式、mermaid、PDF 坐标裁剪目检不过；验收失败 | 已有铁律（path.join、userData、字体栈、\n 归一、静态资源全本地）**继续保留并落实为 CI 断言语义**；双端截图回归纳入每里程碑验收录屏；PDF 裁剪「无切边/渗字」双端各跑一遍 |
| 4 | **SQLite 数据损坏 / WAL 失控膨胀**：非正常退出后库损坏；长开状态下 WAL 无界增长（公开案例：某桌面应用 WAL 涨到 10–15GB 占满磁盘） | 中 | 数据丢失 / 磁盘耗尽 | docs/06 §2.5 的健康自愈基座**必须 M1 落地**：WAL + `synchronous=NORMAL` + `busy_timeout=5000` + `wal_autocheckpoint=1000` + `journal_size_limit` 上限 + 退出/备份/迁移前 `checkpoint(TRUNCATE)`；冷启动 `quick_check→integrity_check`；备份用 `VACUUM INTO` 保留 N 代；损坏进隔离区重建。单写者纪律在此成为硬约束 |
| 5 | **sqlite-vec 升级位落空**：上游停滞，未来要上 HNSW/混合检索时被迫重构 | 高 | 后期里程碑延期或检索方案被迫换车 | 立即改写 docs/03 §2/§11 升级位为三选一（社区 fork sqlite-vec / sqlite-lancedb / 内嵌 LanceDB），并在 M3 前落一个 20 行级 **EmbeddingStore 接口抽象**——MVP 余弦、未来任一后端都实现同一接口 |
| 6 | **AI 生成 HTML 逃逸 / 数据外泄**：故意或失误生成的 `<img src="https://…?data=">` 类外联把笔记内容带出本机；桥被滥用调用主进程能力 | 中 | 数据主权破防（产品核心承诺） | 三件套补全（§1-6）：CSP `default-src 'none'` + 外联资源=0 预检（校验器新规则）+ MessageChannel 白名单桥（只读、按请求校验、导航即断）。另加一套 **escape 冒烟测试**：用含恶意 pattern（外联 img/iframe/form/自我删 sandbox 尝试）的 HTML 素材跑安全用例 |
| 7 | **流式渲染抖动 / 白屏 / 内存膨胀**：高频重渲染掉帧；超长生成的缓冲与回放占用无限增长 | 高 | 核心差异化（验收 10）翻车 | docs/06 §2.1 补工程护栏：三层缓冲（SSE 解析→IR 增量→渲染 keyed 分块）+ 帧预算（单帧超时跳帧渲染）+ 组件级 memo；生成流回放与检查点存储**设容量上限与轮转**；坏段重写、检查点分支机制保留 |
| 8 | **LLM 输出漂移 / 协议坏块**：模型不按 `:::tool` 协议、JSON 破损、SSE 半包 | 高 | 任务失败率升高、演示残缺 | 已有治理（JSON5 恢复、坏块降级原文、重试、坏段重写）方向正确，补：SSE 断点续传与错误码映射、重试退避上限、快照审计可回溯 |
| 9 | **密钥与端点泄密**：settings 明文存 key；日志带 key | 中 | 密钥被盗刷 | settings 中凭据字段**改走 Electron safeStorage API**（macOS Keychain / Windows DPAPI），不写明文；日志统一过脱敏中间层；A/B 端点配置不落盘为明文 |
| 10 | **上/中游依赖低活跃**：fcose/mermaid/morphdom 类库更新停滞、断供或 bug 无人修 | 中 | 升级断供、长期带病 | 锁定 semver + 内部 fork patch 目录（`patches/`）+ 定期（每里程碑）review 依赖活跃度；原则：**能删的依赖删，能自写的薄封装自写** |
| 11 | **多开/单实例失效导致双写**：未正确加锁时两个实例共写同一 SQLite | 低 | 数据损坏 | 启动即 `app.requestSingleInstanceLock()`（方案已提「单实例锁」，设为 M0 验收项）；即便有锁，主进程唯一写句柄 + busy_timeout 仍作为双保险保留 |

## 3. TOP7 硬采纳建议（可直接写入开发方案）

1. **Electron 基线修正（改 docs/03 §2、§3、§9）**：运行时段式改为「Electron 43.x stable（Node v24.17.0 / Chromium 150）+ Node 24 + pnpm 10」；§2 表中「Electron（33+）」与「Node.js 20+」一并更新；§11 预留补充「Electron 每 2 major 升级窗口」例行项。**落点：M0 开工前**——晚改一周等于返工一周。

2. **演示沙箱三件套（改 docs/03 §6.3、docs/06 §2.1）**：`srcdoc` 注入 + `sandbox="allow-scripts allow-forms"`（明确写出「永不 allow-same-origin」）+ 首字节 meta CSP `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:`；桥改 MessageChannel 端口 + 请求白名单（父侧逐条校验），废除裸 postMessage+origin 校验的旧表述；纪律校验器新增「外联资源=0」规则。**落点：M2**。

3. **向量升级位改写（改 docs/03 §2、§11）**：将升级位从「sqlite-vec」改为「三选一：photostructure/sqlite-vec 社区 fork ／ asg017 sqlite-lancedb 混合检索 ／ 内嵌 LanceDB（@lancedb/lancedb）」，并注明 sqlite-vss 已废弃、上游 asg017/sqlite-vec 停滞现状；MVP 维持 JS 余弦不动，但 M3 前落 **EmbeddingStore 接口**（`add/query(embedding, k)/drop`），保证后换实现不改调用面。**落点：docs 修订即刻，接口 M3**。

4. **better-sqlite3 定版与冒烟（改 docs/03 §2、§3）**：锁定 ≥v13（Node-API prebuild 路线的版本），CI 双矩阵加入「原生模块加载冒烟」步骤（内存库 SELECT + 版本断言 + sharp 元数据），替代对 node-gyp/electron-rebuild 的默认依赖；升级 Electron major 的 checklist 中固定「先冒烟后合流」。**落点：M0 CI**。

5. **SQLite 持久化基线（docs/06 §2.5 扩写 + docs/03 M1 验收）**：开库即执行 `journal_mode=WAL; synchronous=NORMAL; busy_timeout=5000; wal_autocheckpoint=1000; journal_size_limit=64MB`；退出、备份、迁移前统一 `checkpoint(TRUNCATE)`；冷启动断言 + `VACUUM INTO` 轮转备份（保留 N=3）；所有写只经主进程唯一句柄。M1 验收从「异常退出后库自动校验恢复」扩为「异常退出 + 长开写入后 WAL 有界、恢复无损」。**落点：M1**。

6. **流式渲染工程护栏（docs/06 §2.1 补充小节）**：明确三段式缓冲（SSE 半包解析 → IR 增量缓冲，50–80ms 防抖 → 渲染层 keyed 分块 memo，不做整文档重渲染）；帧预算与跳帧策略；回放/检查点存储轮转上限；明确「不引入 morphdom」。首帧 ≤2s、无白屏验收项（03 §8-10）保留。**落点：M2**。

7. **Electron 安全基线单列成文（新增 docs/07-安全基线.md → 注意与本文档编号冲突，可记为 08，M0 交付）**：三支柱（contextIsolation:true / sandbox:true / nodeIntegration:false）+ `will-navigate` 拦截 + `setWindowOpenHandler` 全拒 + permission handler + `shell.openExternal` 协议/域名白名单 + typed IPC 参数校验（推荐 zod + 静态 channel 名）+ 主页面 CSP（与演示 iframe 的隔离 CSP 分开管理）+ 预留 fuses（打包阶段启用）。CI 引入 electronegativity 静态扫描（`--severity high` 不放行）。**落点：M0**。
