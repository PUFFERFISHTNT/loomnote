# 织记 · VCP 源码洞察与全栈优化方案（效果优先版）

> 结论在先：通读 VCP 源码后确认——它的价值不只是记忆系统。**流式工具回环、语义级选模、EPA 查询特征分析、推理内容适配、SQLite 健康自愈、资产世代化**等机制对织记整个应用都有直接增益。本版方案以**应用效果为唯一优先级**全面引入，并重新划定合规口径（见 §0）。

## 0. 总则：效果优先下的合规口径

- **数学内核：可用。** 算法思想与数学公式不受版权保护，EPA（加权 PCA/能量共振）、残差能量分解、共现传播等内核**按公式用 TypeScript 独立重写**即可对齐效果；代码文本仍不复制（CC BY-NC-SA 传染条款只约束代码与文档的逐字复制）。
- **效果验证优先**：每个机制先做 20 行级原型验证增益，有增益才进正式管线，不迷信「VCP 用了所以我们也用」。
- **README 标注**「设计启发自 VCPToolBox（lioensky）」并附链接，满足署名（BY）。

## 2. 重点优化详案

### 2.1 实时 HTML 生成（织记最大差异化，其余全为它服务）

**目标**：从用户按「整理」到看到完整演示，全程**连续流**、无「生成中…」白屏。

**管线（正文 + 演示双通道共用）**：

1. **流内工具回环**（仿 VCP 工具 loop）：模型在流中随时发 `:::tool` 指令块 → 主进程执行（裁剪图片 / 查图谱邻域 / 记忆召回 / 生成数据图）→ 结果回填 → 模型**续接原流**。用户从头到尾只看到一条进行中的渲染。
2. **渐进解析**：SSE delta → 增量 markdown 缓冲（不完整块暂存）→ 每 50–80ms 防抖重放 markdown-it 增量渲染 → 正文模式「边想边排版」。
3. **渐进演示渲染**（演示模式关键）：AI 输出 HTML 片段 → 结构性容忍解析器（对未闭合标签/孤儿节点做补齐）→ iframe 内**双缓冲 swap**：旧帧可交互，新帧完整后一次替换，中间态只显示「演示生长中」进度条。
4. **纪律校验器下沉到流**：每个片段落架前过校验（唯一根/前缀隔离/扁平/无 backdrop-filter/动画只 opacity），不合格片段不刷新，超时自动要求模型重写该段（只重发坏段，不整卡重来）。
5. **打断与分支**：每 20 个增量落一次检查点（任务态快照），用户可打断改要求 → 从检查点分支续流；分支历史进「生成流回放」。
6. **{{变量}}模板即配置**：所有生成模板（笔记/演示/题目/摘要）存为可编辑模板文件，带版本与回滚。

### 2.2 语义级模型路由 + 查询特征预分析（吃透 EPA 的应用方式）

VCP 的 EPA 真正用途是**在每次调用前对查询向量做特征分析**（逻辑深度、熵、覆盖度、跨域共振），路由与注入参数随特征动态变化。织记对标：

- **特征预分析器**（TS 自写）：输入任务描述 + 上下文向量 → 输出 `{ logicDepth, entropy, coverage, novelty }`。V1 用「嵌入 + 与图谱/记忆库的距离分布」近似：深度≈高密度专业词，熵≈话题分散，coverage≈被现有知识的解释比例，novelty≈残差能量比（残差金字塔的语义版）。
- **动态决策表**（全部可配置、可被规则蒸馏改写）：
  - coverage 高（熟题）→ 记忆注入走摘要层、模型用轻档；
  - novelty 高（全新领域）→ 注入全量关联 + 强模型 + 优先生成**演示组件**（新知识用演示学最快）；
  - logicDepth 高 → 倾向「思路展开」模式 + 推理档模型。
- **跨模型无缝**：上下文全部归一为「织记标准装配体」（记忆包裹 + 任务声明 + 模板输出契约），切换模型不丢状态（对齐 SemanticModelRouter 的跨模型持久化设计）。

### 2.3 「思路展开」面板（学习应用独有增益）

仿 reasoningContentAdapter：推理模型的 reasoning 流单独通道接收 → 拆为步骤节点 → **_实时_**渲染成可折叠的「思路展开」卡片（步骤间可带勘误标记「注意：此处绕了远路」由轻模型后评注）。学习场景下，看 AI 怎么想 = 最高价值的教学材料；设置里可关（省 token）。

### 2.4 可观测三件套

- **上下文快照审计**：每次装配的完整注入包落快照（滑窗 5–20），用户可展开「AI 刚才看到了什么」；配合偏好修正，用户能直接解释「为什么它没遵守规则」。
- **生成流回放**：工具回环、delta 序列、分支历史全部落盘，可逐帧回放生成过程（Debug 界面）。
- **记忆管理界面**：偏好/规则/事件流水可视化（倒序 + 过滤 + 删除 + 导出），与 doc 05 的 audit 贯通。

### 2.5 本地库健康自愈（抄 VCP 的生产级态度）

- busy timeout + 单写者约束（主进程独占写，渲染进程只读 IPC）；
- 应用冷启动跑完整性断言（`PRAGMA integrity_check` + 行数水位）→ 异常进隔离区并自动从最近自动备份恢复；
- 每次迁移前自动备份；checkpoint 策略：静默窗口 + N 次写后；
- 崩溃恢复：写前日志（WAL）+ 启动回放，保证「写一半断电」不丢已提交数据。

### 2.6 资产世代化（照搬 VCP 的工程纪律）

一切**派生物**（图谱指标、MOC、tag 共现、画像、向量基线）都遵守：不可变资产包 + 世代版本 + 一次性原子发布 + 后台防抖重建（阈值触发，如新增 50 个唯一 tag 才重算）。请求路径永远只读，界面永不被重算卡住；旧世代保留一份供回滚对照。

### 2.7 数学内核落地策略（效果优先口径）

- **立刻用（TS 重写对齐效果）**：余弦（已有）、残差能量分解（查询新颖度）、共现矩阵 + 单步传播（boost）、加权 PCA-lite（逻辑深度，仅上线性代数 JS 实现）、能量阈值截断。
- **P2 再评估（性能瓶颈实测后）**：>10 万记忆后的近邻检索上 HNSW（sqlite-vec），热路径（批量相似度）下放 worker/Rust；在此之前全 TS，避免过早优化。

### 2.8 权限门禁

高风险动作白名单制：删除节点/边、批量合并变更集、向飞书/Notion 真实写入、清空记忆——一律 UI 显式确认 + 可定时效（本次会话内放行）。AI 自动批处理只能产草稿变更集，永不自批。

## 4. 对开发方案（03）的改动清单

1. M1 增：SQLite 健康自愈基座（WAL/完整性断言/备份/隔离区）。
2. M2 增：流内工具回环、渐进渲染双通道、双缓冲演示帧、查询特征预分析器、语义级动态路由。
3. M3 增：资产世代化（图标/索引/画像按世代重建）、权限门禁、可观测 v1（快照审计）。

5. 验收新增：按压「整理」到首帧出内容 ≤2s 且过程连续无白屏（本地模型外）；打断后可从检查点分支续流；断流/坏段自动重写坏段而非整卡重来。
