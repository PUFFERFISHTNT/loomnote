# 04 · 记忆引擎与智能进化（终稿）

> 源自对 lioensky/VCPToolBox 记忆体系源码的逐文件调研（约 15,000 行 / 20+ 文件），按「架构照搬、数学内核按公式 TS 重写、代码零复制」落地。过程稿 05 为调研全记录。

## 1. VCP 记忆体系的源码结论

**写入层（TagMemo）**：句级分块（85% token 预算 + 10% 重叠 + 标点强制断）→ 内容哈希幂等去重 → 批量嵌入 → Tag 提取 → SQLite/向量双落 → 后台防抖重建派生物（共现矩阵/残差资产/正交基），在线路径只查表。

**召回层（RiverMemo）**：查询向量 → EPA 特征（逻辑深度/熵/跨域共振）→ 候选超集 6 路过取（向量多场 KNN×4 + BM25 + 直锚，各 k×3）→ hard+semantic 去重 → 共现核传播 boost（1.2–1.4×）→ 残差金字塔能量解释（90% 截断）→ 相对拓扑/曲率成对修正 → Ω 结构证据排序 → 有序原文读出。

**注入层**：预算守卫修剪（system/末轮硬保留）→ 折叠块（阈值+摘要）→ 上下文快照留档。

**进化线**：写记忆是行动（Tag 是叙事河床）；资产不可变+世代版本一次发布；冷热双通道；跨空间联想发现。

## 2. 织记记忆引擎（VCP 式自建，零外部服务）

### 2.1 分层模型

| 层 | 内容 | 存储 |
|---|---|---|
| L0 任务上下文 | 当前生成流/任务态 | 内存 |
| L1 语义知识 | 笔记/知识点/资源（切块+向量+三级摘要） | SQLite + 向量 |
| L2 用户偏好 | 排版/公式/图片/模型/工作流习惯 | prefs（带版本） |
| L3 行为事件 | 采纳/修改/重生成留痕（含 diff） | behavior_events |
| L4 经验规则 | 蒸馏出的可执行规则（模板变量/路由/校验） | rules（带版本） |

### 2.2 写入 / 召回 / 注入

- **写入**：ingest（chunker→dedup→embed→tag→分层摘要）幂等可重跑；行为事件流水常开；偏好显式/隐式双通道。
- **召回三通道**（各过取 k×3 统一去重）：向量相似 / 图谱邻接 / 行为共现；核心 tag 加权 + 边单步传播；直锚原则（原文随候选返回，摘要不替原文）。
- **注入**：`buildMemoryPackage(任务, 预算)` = 召回 top-k + 图谱邻域 + 偏好快照 + 生效规则 → 预算内全量、超出折叠（阈值+摘要块）→ 装 `{{记忆包裹}}` / `{{注意力包裹}}` 槽 → 审计快照。
- **冷热**：近 14 天学习/薄弱/高频 = 热全量在场；归档 = 冷库折叠索引，按需唤起。

### 2.3 自进化闭环（五步）

观察（行为流水）→ 蒸馏（**Mem0 化两阶段**：事实抽提 → 每域 ≤8 条聚簇固结 → 聚簇成规则；≥2 正样本，弱模型+统计双路）→ 生效（高置信自动/中置信弹问，写入 L4，活跃规则 ≤20 条）→ 反馈（效果指标：修改率/重生成率变化，影子灰度对照）→ 演化（晋升/降级/停用/冲突询问）。验收红线：**纠正一次（如「公式用单 $」）→ 之后同类生成自动遵守**。

## 3. 模块与核心契约

```
packages/memory/src/
├── chunker.ts embeddings.ts dedup.ts store.ts layers.ts
├── recall/{channels,boost,anchors,rerank}.ts
├── fold.ts packager.ts rules.ts audit.ts engine.ts
```

- API：`ingestDocument / recordBehavior / recall / buildMemoryPackage / distillRules / getActiveRules / getPrefs`
- 数据表：memories / sources / tags / tag_edges（带时序失效衰减，06 C3）/ behavior_events（保留 30 天，06 C6）/ rules / prefs / artifacts / audit_snapshots
- 关键参数（均可配置）：预算 85%、重叠 10%、过取 k×3、去重阈值 0.92、boost 1.2–1.4、热窗口 14 天、折叠阈值 0.6、快照滑窗 5–20
- 依赖：TS 独立实现，仅 SQLite；嵌入走 Provider 框架「向量」角色；无原生模块（better-sqlite3 由主应用提供注入或独立引入，测试注入假实现）

## 4. 与 Harness Agent / 查询特征预分析的协同

1. agent 的**决策输入**：每任务前特征预分析（logicDepth/entropy/coverage/novelty，EPA 的 TS 语义版）→ 决定记忆注入深度（熟题摘要层、新领域全量+强模型+优先生成演示）。
2. agent 的**行动输出**：agent 在流内用 `recall_memory` 工具主动补查；写笔记时触发写入管线；用户纠正经行为流水回流 L3。
3. **合规口径**：算法与数学公式不受版权限制，Ω/EPA/残差能量等按公式 TS 重写对齐效果；代码文本不复制；README 标注启发来源（CC BY-NC-SA 的 BY）与链接。

## 5. 量化护栏与评测标准（06 决议 C1/C6，M2 起生效）

- **评测回归集先行**：20–30 条多跳题 + 10 条偏好遵守检查，固定种子素材；每版指标 = nDCG@10 + 偏好遵守率，挂 CI。
- **预算硬帽**：记忆包裹 ≤1200 tokens（硬帽 1600，弃用 85% 比例制）；熟题注入 ≈300；工具回环 ≤3 次/任务；坏段重写 ≤2 次；蒸馏每周 1 次 × ≤200 事件。
- **噪声闸门**：语义去重 0.92 + 同源同 Tag 双条件；min_score 0.40；单通道 top-8~16；活跃规则 ≤20 条；检查点差异快照 ≤1 次/秒、≤20 份/任务。
- **隐私补全**：ingest / distill 两端 PII 过滤器；嵌入出网需显式授权 + 本地嵌入开关；行为/规则/快照三表永不同步云端。

## 6. 实现状态与阶段

**已实现（M0–M2，均有单测）**：chunker（句级/预算/重叠/强制断）· dedup（哈希+语义 0.92）· NGramEmbedder/FakeEmbedder（离线可用）· recall（三通道基础：向量+tag boost；图谱邻接/行为共现通道待图谱引擎）· fold（预算折叠）· packager（记忆包裹 ≤1200/硬帽 1600）· RuleBook + distillRules（≥2 正样本）· MemoryEngine 门面（幂等摄取/行为流水 30 天/审计滑窗 20）。

**阶段**：M1 存储+埋点 ✅ → M2 召回 v1+记忆包裹 ✅ → M3 三通道齐 + SqliteMemoryStore + 资产世代 → M4 蒸馏闭环+管理界面+快照审计。
