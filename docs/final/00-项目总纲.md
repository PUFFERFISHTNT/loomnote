# 00 · 项目总纲（终极定稿 · 项目宪法）

> 本文档是全项目的「宪法」：定位、原则、边界、文档地图与决策记录。任何后续开发与此冲突时，以本文为准（修改需走 06-评审决议 同款流程）。

## 1. 项目身份

- **产品名**：织记 LoomNote（工作名，待最终确认）
- **形态**：Windows + macOS 双端独立桌面应用（当前阶段 = 开发测试版，`pnpm dev` 启动，不打包不签名）
- **一句话定位**：把原始资料交给 AI，产出**能看（多格式渲染）、能演示（动态 HTML）、能考试（交互判分）、能联网（知识图谱）、能成长（记忆自进化）**的活笔记。

## 2. 边界三铁律

1. **独立应用**：自有 UI、自有工程、自有品牌，与 DSH 桌面/插件生态完全解耦；harness 只是被内嵌的底层。
2. **内容主权在本地**：SQLite + 本地资源库为唯一事实源；飞书/Notion 云端仅是同步副本；断网可启可编。
3. **数据零依赖**：记忆、图谱、偏好全部随应用启停，不依赖任何外部常驻服务；AI 模型接入自由（任意 OpenAI 兼容/Anthropic/自定义端点）。

## 2.5 「Harness Agent」定义（织记的 AI 引擎本体）

织记底层是一个**完整的 harness agent，而非模型调用客户端**：

- **能自主行事**：面对任务自主「规划 → 调用工具 → 观察结果 → 修正 → 交付」，多步循环直到完成；
- **能调用工具**：工具注册表管理一切能力（详见 03 §5），**内置联网搜索/网页抓取**、文件读写、OCR 识图、本地知识检索、图谱查询、公式计算等；
- **双协议兼容**：优先用原生 Function Calling（适配火山方舟 Agent Plan 等支持工具调用的端点）；模型不支持时自动降级为**文本标记工具协议**（`:::tool` 指令，容忍解析），任何模型都能当 agent 用；
- **有纪律**：每步有超时、预算与重试；危险工具（删改数据、外部写入、联网外发）必须用户审批；全程事件流可视化（想什么、调了什么工具、结果如何都可见、可打断、可分支）。
- 与 DSH 的关系：**代码同源（MIT 包直接复用），产品独立**——织记通过 npm 依赖复用 DSH 的 agent-loop / Provider / 联网工具等官方包（03 §5），但 UI、插件体系、桌面壳、数据层完全自建，不依赖 DSH 桌面。

## 3. 设计三原则

1. **MD 为底，HTML 为面**：Markdown IR 是唯一事实源（可版本、可迁移、可导出）；展示层由 AI 按知识点需要生成——普通内容排版卡、需演示的知识点生成 HTML5 交互演示。
2. **一切皆可渲染**：md/PDF/Word/Excel/图片/URL 解析进同一 IR，按通道分流渲染（应用三模式 / 飞书 / Notion / 导出），所见同源。
3. **笔记会生长**：新资料不触发整本重写，AI 只做「找接缝 → 出变更集 → 快照合并」；偏好在使用中自蒸馏、自动生效（自进化）。
